# Diccionario de datos

Los importes se expresan en pesos colombianos y las cantidades admiten tres decimales para venta por peso. Una columna permite NULL si carece de NOT NULL y no pertenece a la clave primaria. REFERENCES sin columna apunta a id.

## area — Área operativa

| Campo | Tipo y restricciones SQL | Significado |
|---|---|---|
| id | `integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Identificador interno. |
| nombre | `text NOT NULL UNIQUE` | Nombre del área. |

## oferta — Acuerdo entre proveedor y producto

| Campo | Tipo y restricciones SQL | Significado |
|---|---|---|
| proveedor_id | `integer NOT NULL REFERENCES proveedor` | Proveedor que ofrece el artículo. |
| producto_id | `integer NOT NULL REFERENCES producto` | Artículo ofrecido. |
| costo | `numeric(14,2) NOT NULL CHECK(costo>=0)` | Costo pactado por unidad. |

## lote — Partida física de un único producto

| Campo | Tipo y restricciones SQL | Significado |
|---|---|---|
| id | `integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Identificador interno. |
| producto_id | `integer NOT NULL REFERENCES producto` | Producto de la partida. |
| codigo | `text NOT NULL` | Código del fabricante o código interno. |
| ingreso | `date NOT NULL DEFAULT current_date` | Fecha de registro de la partida. |
| vence | `date` | Fecha de vencimiento, obligatoria para perecederos (la exige el trigger `validar`) y no anterior al ingreso. |
| saldo | `numeric(14,3) NOT NULL DEFAULT 0 CHECK(saldo>=0)` | Existencias físicas en la unidad base. |

Restricciones de tabla: `UNIQUE(producto_id,codigo)`, `CHECK(vence IS NULL OR vence>=ingreso)`.

## compra — Pedido al proveedor

| Campo | Tipo y restricciones SQL | Significado |
|---|---|---|
| id | `integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Identificador interno. |
| fecha | `timestamptz NOT NULL DEFAULT now()` | Instante de registro. |
| empleado_id | `integer NOT NULL REFERENCES empleado` | Persona responsable de la operación. |
| proveedor_id | `integer NOT NULL REFERENCES proveedor` | Empresa que suministra el pedido. |
| estado | `text NOT NULL DEFAULT 'PENDIENTE' CHECK(estado IN ('PENDIENTE','RECIBIDA'))` | Etapa de recepción. |
| fecha_recepcion | `timestamptz` | Instante de la recepción; NULL mientras esté pendiente. |
| receptor_id | `integer REFERENCES empleado` | Persona que recibió la mercancía; NULL mientras esté pendiente. |

Restricciones de tabla: `CHECK((estado='RECIBIDA')=(fecha_recepcion IS NOT NULL) AND (estado='RECIBIDA')=(receptor_id IS NOT NULL))`. En compra, empleado_id es quien registró el pedido y receptor_id quien lo recibió.

## Información calculada

Inventario.existencia suma los saldos por producto. Inventario.estado da prioridad a DESCONTINUADO, luego AGOTADO si el saldo es cero y DISPONIBLE en otro caso. Los totales de compras y ventas suman los subtotales históricos. Rotacion_30d agrega cantidades vendidas en los últimos 30 días por producto y unidad.

## Funciones y trigger

Todas las funciones son `SECURITY DEFINER`, identifican al empleado con `session_user` y se ejecutan completas dentro de la transacción de quien las llama: si algo falla, no queda nada registrado.

| Rutina | Rol autorizado | Qué hace y valida |
|---|---|---|
| responsable() | uso interno | Devuelve el id del empleado de la sesión. |
| registrar_compra(prov, lineas) | bodega | Crea la compra pendiente. Cada renglón debe tener acuerdo con el proveedor; el costo se toma de la oferta y, si se informa, debe coincidir con ella. |
| recibir_compra(doc) | bodega | Pasa la compra a RECIBIDA una sola vez, suma los saldos y guarda fecha y receptor. |
| registrar_venta(cliente, medio, lineas) | caja | Crea la venta, descuenta saldo de lotes vigentes y fija el precio de catálogo en cada renglón. |
| registrar_solicitud(det, clase, cant, razon) | atención | Registra la solicitud; la suma de devoluciones no puede superar lo vendido. |
| registrar_movimiento(partida, clase, cant, razon, solicitud) | bodega | Registra el cambio de existencias. VENCIMIENTO exige un lote ya vencido y DEVOLUCION_CLIENTE una solicitud compatible. |
| validar_lote() (trigger `validar`) | automático | Exige vencimiento a los productos perecederos. |
